# Packet 4H input audit

This is a source audit of the native 0.3.27 diagnostic producers, ahead of a shadow-only bridge. It establishes requirements, not a new live acceptance result. No current producer supplies exact calibrated contact speed or a complete component-bound impact snapshot. Native damage, wear and stagger authority remain disabled.

## Readiness matrix

| Input | Available evidence | Remaining requirement |
| --- | --- | --- |
| Hit identity | Session, projectile lifetime, source, target, carrier, weapon and ammunition; receiving actor/process checks | Bind every producer to the same explicit component and application; diagnostic context, lifetime and transaction IDs are distinct |
| Contact speed | Observed engine-segment mean or owned-step interval; optional point-model candidate | Exact contact-time/point association, verified producer and calibrated units; no current producer satisfies these |
| Contact region | Separate literal collision and hit-data regions | Verified agreement or an explicitly tested disagreement policy; no enum cast or torso fallback |
| Worn equipment | Bounded complete double traversal, call-local instance tokens, record and condition values | Coherent at-impact ownership, actual struck instance, verified layer order and complete surface set |
| Coverage/materials | Exact-origin authored coverage classification | Actual contact, material/target bindings, natural/mechanical completeness and production profile evidence |
| Application | Exact CopyHitData pointer association inside a guarded provider-call scope | Component/application ownership and exact-once policy; provider return does not prove committed loss |

## Contact producer findings

The first engine segment is reported as translation mean speed with a numerical allowance, not measured contact speed ([FlightContactSpeed.inl:66](../../../../native/NVOCombatCore/src/FlightContactSpeed.inl#L66)). Owned steps produce an interval enclosing the authored ODE, not a selected point on that interval ([FlightContactSpeed.inl:79](../../../../native/NVOCombatCore/src/FlightContactSpeed.inl#L79)). The separate point-model search explicitly returns `model_estimate_only` ([FlightImpactModel.inl:33](../../../../native/NVOCombatCore/src/FlightImpactModel.inl#L33)). Even a narrow or zero-width interval cannot establish an exact producer. The 70 game-coordinate units per simulation metre convention remains uncalibrated ([3V AUDIT.md:30](../step3v/AUDIT.md#L30)).

The collision reader verifies tracked projectile, base, weapon and source identity, then reads the first collision target, point, raw material and literal region ([FlightImpact.inl:57](../../../../native/NVOCombatCore/src/FlightImpact.inl#L57), [FlightImpact.inl:72](../../../../native/NVOCombatCore/src/FlightImpact.inl#L72)). World, Reference and Invalid remain separate; an actor join requires a matching nonzero Reference target. Hit pairing additionally requires matching lifetime, projectile, source, weapon and nonzero ammunition ([FlightImpactJoin.inl:19](../../../../native/NVOCombatCore/src/FlightImpactJoin.inl#L19)). The public observation entry checks the active session ([FlightPhysics.cpp:1204](../../../../native/NVOCombatCore/src/FlightPhysics.cpp#L1204)).

The `paired` result compares retained collision data with a later collision reread, including their points ([FlightImpactJoin.inl:34](../../../../native/NVOCombatCore/src/FlightImpactJoin.inl#L34)). It does **not** prove that the hit-data position denotes that contact: query position is only checked for finite values and logged ([FlightImpactJoin.inl:51](../../../../native/NVOCombatCore/src/FlightImpactJoin.inl#L51)). Region disagreement remains visible, and diagnostic speed can still be logged with no region authority ([FlightImpactJoin.inl:45](../../../../native/NVOCombatCore/src/FlightImpactJoin.inl#L45), [FlightImpactJoin.inl:60](../../../../native/NVOCombatCore/src/FlightImpactJoin.inl#L60)). Pre-movement contacts, missing samples and queries after the callback cannot supply this speed evidence ([FlightImpactJoin.inl:28](../../../../native/NVOCombatCore/src/FlightImpactJoin.inl#L28)).

These are bounded diagnostic samples: 32 collision lifetimes, retained until reset, and 64 hit queries ([FlightImpact.inl:36](../../../../native/NVOCombatCore/src/FlightImpact.inl#L36), [FlightImpact.inl:95](../../../../native/NVOCombatCore/src/FlightImpact.inl#L95), [FlightImpactJoin.inl:3](../../../../native/NVOCombatCore/src/FlightImpactJoin.inl#L3)). Missing or omitted evidence must stay missing; a future bridge cannot reuse an earlier sample or use these budgets as a gameplay ledger.

## Scope and snapshot findings

The CopyHitData observer obtains a `CopyScope` and passes it to armour, then invokes the current-hit observer separately ([CurrentHit.cpp:24](../../../../native/NVOCombatCore/src/CurrentHit.cpp#L24)). The latter builds a flight query containing session/context/lifetime and form identities, without transaction/application identity ([NativeObserver.cpp:343](../../../../native/NVOCombatCore/src/NativeObserver.cpp#L343), [FlightPhysics.hpp:19](../../../../native/NVOCombatCore/include/FlightPhysics.hpp#L19)). Log adjacency cannot fill that missing binding.

`CopyScope.valid` establishes exact supplied pointer, identity, receiving process, current main thread and untainted active call scope ([HitTransaction.cpp:373](../../../../native/NVOCombatCore/src/HitTransaction.cpp#L373)). The transaction ID is assigned per provider call; multiple CopyHitData stages can share it ([HitTransaction.cpp:125](../../../../native/NVOCombatCore/src/HitTransaction.cpp#L125), [HitTransaction.cpp:370](../../../../native/NVOCombatCore/src/HitTransaction.cpp#L370)). It is not a unique copy ordinal, verified damage component or committed application. Provider-return logs explicitly retain `committed_loss=unverified` ([HitTransaction.cpp:154](../../../../native/NVOCombatCore/src/HitTransaction.cpp#L154)).

Armour eligibility requires valid, current-session, untainted main-thread scope; only Character targets (`0x3B`) proceed, with at most 64 snapshot attempts ([ArmourSnapshot.cpp:14](../../../../native/NVOCombatCore/src/ArmourSnapshot.cpp#L14), [ArmourSnapshot.cpp:69](../../../../native/NVOCombatCore/src/ArmourSnapshot.cpp#L69), [ArmourSnapshot.cpp:227](../../../../native/NVOCombatCore/src/ArmourSnapshot.cpp#L227)). Identity/region/flags/process are checked around capture, and a changed boundary or tainted observation discards the snapshot ([ArmourSnapshot.cpp:119](../../../../native/NVOCombatCore/src/ArmourSnapshot.cpp#L119), [ArmourSnapshot.cpp:241](../../../../native/NVOCombatCore/src/ArmourSnapshot.cpp#L241)). These checks and two bit-identical traversals establish bounded consistency, not an atomic impact snapshot ([ArmourSnapshotReader.hpp:81](../../../../native/NVOCombatCore/include/ArmourSnapshotReader.hpp#L81)).

Instance tokens identify items only within that call ([ArmourSnapshotReader.hpp:46](../../../../native/NVOCombatCore/include/ArmourSnapshotReader.hpp#L46)). Region completeness, layer order, impact snapshot and bare-region flags remain unproven ([ArmourSnapshotReader.hpp:70](../../../../native/NVOCombatCore/include/ArmourSnapshotReader.hpp#L70)). Coverage integration explicitly reports authored classification only, with coverage authority zero and no verified layer order or bare region ([ArmourCoverage.cpp:60](../../../../native/NVOCombatCore/src/ArmourCoverage.cpp#L60), [ArmourCoverage.cpp:94](../../../../native/NVOCombatCore/src/ArmourCoverage.cpp#L94)). Equip masks, empty worn sets and inventory traversal order therefore cannot become contact, bare anatomy or layer ordering.

## Smallest next integration work

1. **Enforce offline provenance first.** Give independently supplied speed, region and snapshot evidence composite stamps binding session, component, application, source, target, carrier, weapon, ammunition and profile. Check equality with the requested preview identity before arithmetic. Explicit producer kinds must prevent segment means, intervals and point-model candidates from becoming exact evidence. Matching synthetic stamps exercise the contract only; they do not create a live producer.
2. **Define component-bound capture.** Specify how a supported projectile component and application are identified at the capture boundary, keeping provider transaction, copy ordinal, diagnostic context and lifetime separate. Carry copied scalar evidence through that same boundary with session/reentrancy/exception guards. Define omission, reload and duplicate behavior without relying on log order or cache capacity. Establish what makes the equipment/surface state coherent at the actual impact; stable reads alone are insufficient.
3. **Resolve exact contact input.** Establish a verified speed producer at a proven contact time and point, with documented unit calibration and identity binding. Validate against engine behavior, including pre-movement contacts and supported flags. Keep interval evidence diagnostic unless a separately designed interval resolver is introduced; never choose its mean or endpoint to satisfy the scalar contract.
4. **Complete region and material bindings.** Preserve both literal region IDs and establish the region policy. Bind actual contacted worn/natural/mechanical surfaces, complete sets, condition and independently verified order to the same application. Map target anatomy and material definitions explicitly; raw engine material IDs and authored coverage do not supply those mappings. Require explicit bare evidence and supported kinetic/target profiles.

Mode, modifier ownership, exact-once admission and future committed application remain separate gates. This audit and the offline contract do not install a plugin, introduce engine reads/hooks, enable gameplay writes, or establish live acceptance.
