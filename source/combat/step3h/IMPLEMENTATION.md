# Native318 implementation and reversal

Adds HitTransaction.hpp/cpp and a generated ITR compatibility fingerprint include. Six existing Actor::HitMe call operands route through index stubs to an entry bridge, then tail-dispatch to the corresponding unmodified ITR thunk. A successful diagnostic frame replaces the return continuation; the return bridge restores it after logging. Arguments, integer registers, EFLAGS, DF, x87, SSE and MXCSR are preserved. Each provider thunk continues to call its original engine target once; no second HitMe call is made by NVO.

Guards require the fixed supported game image, exact ITR image metadata, normalized hashes of all six complete thunks and their recorded originals equal to0089A760. Every game call must currently point to its own expected thunk. All code-page protections are acquired before writes; targets are rechecked, originals published, and changes roll back on failure. Guards are checked again per capture. A failure logs HIT_TX_DISABLED, leaving damage replacement off. Provider internals, vtables and full damage implementation are not patched. Detailed disassembly remains in the workspace inspection folder, not the release.

The existing CurrentHit bridge is unchanged; its C++ callback invokes a separate copy-input observation before the old context cap. Existing ITR event callbacks likewise notify the scope observer before their log caps. NativeObserver adds only an identity lookup. Transaction code never holds its lock while calling that lookup; observer/damage-to-transaction-to-logger ordering has no reverse edge. All flight/model/tolerance/profile sources are unchanged.

Static evidence pins source deltas, build/PE32/PDB identity, normalized provider fingerprints, log-format bounds and old compiled bridge comparisons. The offline x86 probe includes the actual transaction source and bridges with mock forms/provider/logging. It checks six-route chaining and unchanged inputs; stack/GPR/flags/DF/x87/SSE/MXCSR preservation; nested overflow; detail/sink exhaustion; suspend and inactive passthrough; two-thread scope separation. It does not load the plugin DLL, launch New Vegas or substitute for the live checkpoint.

Installation changes only NVOCombatCore.dll and its PDB and preserves the previous pair in the installation backup. It verifies all protected files and activation lists. No new kit, INI, dependency, ESM/ESP edit, GECK compilation or game launch.

To reverse: close New Vegas, then restore **both** NVOCombatCore.dll and NVOCombatCore.pdb from the recorded backup's originals/Data/NVSE/Plugins folder to the game's corresponding folder. This restores native317. The installation receipt gives the exact backup path. No saved-game migration is introduced by this diagnostic packet.
