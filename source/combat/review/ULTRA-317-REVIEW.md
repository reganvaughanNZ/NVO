Returning one multiplier at both stages would risk double scaling; that is a future implementation hazard, not an observed duplicate application.

## Existing-pilot and future-interface limitations

**317-07 — Medium, confirmed non-vanilla fallback limitation.** Selection switches to a private non-hitscan, zero-gravity projectile before creation. Physics admits at most 128 active lives, and a rejected life stops subsequent edits (FlightPhysics.cpp:115–119, 1050–1066). A later rejection or capacity miss leaves the selected private projectile; it does not restore original stock trajectory or preserve the last integrated velocity automatically. FlightPreview.cpp:499 only tests module readiness before selection, not a reserved tracking slot. This was already honestly noted in the 3F review. No 317 overflow/rejection occurred, so this is not a newly observed regression or reason to loosen guards. Before wider activation, reserve admission before selection where possible and define a safe terminal policy for post-selection failures. Record fallback reason independently of routine log availability.

**317-08 — Medium, confirmed diagnostic-only capacity boundary.** Current-hit processing stops after 200 contexts; the impact cache admits the first 32 lifetimes per load; hit joins stop after 64. Those caps are appropriate for diagnostics and must never become damage coverage caps. The logger is bounded per process, including a finite priority reserve, and file errors/caps can suppress output while physics continues. Independent application state must survive diagnostic exhaustion and must handle session resets, retirement, duplicate encounters and overflow explicitly. Keep the current bounded logs; do not solve this by unbounded caches or log growth. Native317 intentionally exposes no damage API, so this is a requirement for the next interface, not an existing damage bug.

**317-09 — Low, distribution evidence gap.** GPLv3/JIP and MIT/ITR notices are retained, and the source/build delivery is present. BallistX credits retain the planning record's commercial-sale restriction for donor assets, while G1/G7 samples are compiled into FlightDragData.hpp. The provided permission summary does not settle the exact scope of that restriction for copied numeric tables and this combined delivery. Preserve all notices, obtain/store the applicable source permission text or replace/separate the disputed data before making a broad redistribution-license claim. This review does not decide legal infringement or block private diagnostic work. Future unused donors do not need a fresh license audit until a specific feature is actually adapted.

## Native invariants that passed the scoped review

- Fixed-runtime/image guards, JIP function fingerprints and vtable ownership checks are present. CurrentHit installs with compare/exchange and preserves the original tail call. Physics normalizes only exact owned hook spans and installs its nine code patches at deferred initialization, with protection/cache handling and rollback attempts. Subsequent capture guards reject foreign code. Installation relies on the existing deferred-startup/no-concurrent-execution assumption; a future new hook requires its own affected-path review.
- Naked wrappers preserve integer registers, EFLAGS, x87/SSE/MXCSR; the source uses aligned FXSAVE space, clear direction flag and temporary clean FP state for C++ work. Local-Z fallback reproduces the displaced FLDZ/FSTP with the extra return-address offset. TerrainBridge invokes the original query once and preserves its returned AL, restricting its correction to the checked private applied step and failed default result. Existing static evidence reports all nine physics bridges unchanged in 317.
- Lock order is observer to physics/timing to logger. Physics/timing do not call back into the observer or engine behavior while holding their locks. Event binding and console notices are kept outside the observer lock. No lock cycle was found in the current call graph.
- Pointer identity uses monotonic lifetime serials; creation handles reused addresses, destruction retires before provider free, and reload/exit clear transient tracks. Timing return continuations use per-thread LIFO frames that lifecycle reset deliberately does not erase; overlap and nesting limits fail closed for diagnostics. ShowOff destruction dispatch is synchronous in the inspected provider route. There is no supported hot unload; retained hooks/TLS assume the module stays loaded until process exit. Normal exit logs do not prove no later shutdown crash.
- Parser bounds, duplicate fields/matches, exact weapon/ammo/base identity, load-index resolution, guarded reads, explicit unknown ammo, private record comparisons and finite-number checks are present. AP/HP have distinct identities but intentionally share standard .308 flight tuning. Those values do not imply material or penetration differences.
- The observed contact/region join copies scalars, checks current session/lifetime/source/target/weapon/ammo, rejects changed/multiple/unavailable/late contacts, and does not mutate damage, region or flight Track values. The prior failed-terrain/range checkpoint remains accepted within its observed scope; 317 does not re-exercise it and does not invalidate it.
